# 卡内容修复指南（图播不出来 / 黑屏 / 数码管显示 00）

> 结论：工程**只能读「24bit、不压缩（BI_RGB）、bottom-up」的 BMP**。
> 你卡上的文件如果是 JPG / PNG（或 32bit / 带压缩的 BMP），扫描会**一张都认不出**，
> 于是没有可播的图 → **画面全黑 + 只剩开机横幅**，数码管登记数显示 `00`。
> 这**不是花屏**，是「没有图」。

---

## 一、先把「黑屏」和「花屏」分开

| 现象 | 含义 |
|---|---|
| 画面全黑 + 只有两行横幅文字 | **没有图可播** → 卡内容问题（本页解决） |
| 有图，但画面错位/错色/撕裂 | 才是渲染/时序问题 |

判据：**看数码管上那个两位数**（十六进制，我加的登记张数）。
`00` = 一张都没扫到；`08` = 扫到 8 张。

---

> 这组图故意做成 8 种分辨率 —— 正好演示"图片自适应缩放（扩展3）"：
> 宽图自动上下补黑边、高图自动左右补黑边、320×240 放大 2 倍铺满。

**尺寸怎么选？**

## 四、卡本身的要求

- 文件系统 **FAT32**（或 FAT16）
- 图片放在**能扫到的位置**（根目录最省事）
- 卡里**不要有名为 .bmp 实为 JPG 的假文件** —— 官方工具会报「magic 不是 'BM'」

---

## 五、卡格式速查（官方 bmp_check.py 点名的坑）

| 坑 | 后果 |
|---|---|
| PNG/JPG 直接改后缀成 .bmp | magic 不是 'BM'，认不出 |
| 32bit 带 alpha / 8bit 带调色板 | 位深不是 24，认不出 |
| BI_RLE8 / BI_BITFIELDS 压缩 | 工程读不出来 |
| height 为负（top-down） | 显示上下颠倒 |
| 分辨率不匹配 | **显示错位或花屏** |
